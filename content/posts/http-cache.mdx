再次打开一个页面，并不意味着浏览器必须重新下载所有内容。缓存是否可以复用，取决于响应的缓存规则以及资源是否仍然有效。

## 先判断是否还新鲜

`Cache-Control` 可以告诉缓存一份响应允许复用多久。在允许缓存的前提下，`max-age=300` 表示它的最大新鲜时间为 300 秒。

```http
Cache-Control: public, max-age=300
```

过了新鲜期，并不等于资源内容一定发生了改变。客户端可以再向服务器确认。

## 用条件请求确认变化

服务器可以返回 `ETag` 作为资源表示的验证标识。后续请求携带 `If-None-Match`，让服务器判断已有内容是否仍可使用。

```http
If-None-Match: "article-v3"
```

当条件满足时，服务器可以返回 `304 Not Modified`，客户端据此复用已保存的响应体。这节省了重复传输正文的开销。

## 读懂几个容易混淆的指令

| 指令 | 要点 |
| --- | --- |
| `no-cache` | 复用前需要向服务器验证 |
| `no-store` | 要求缓存不要存储响应 |
| `private` | 限制共享缓存存储响应 |
| `public` | 允许共享缓存按适用规则存储响应 |

`no-cache` 的名字容易让人误解。它关注的是使用之前的验证，而不是禁止保存。

## 公共资源与个人数据分开考虑

带内容指纹的静态文件适合较长时间缓存。个人中心、登录状态和用户私有数据则需要谨慎设置缓存策略，避免共享缓存把同一份响应交给不同的人。

检查缓存问题时，可以从浏览器的网络面板看状态码、响应头和请求头，逐个确认：是否存储、是否仍然新鲜、是否发起了条件请求。
